# 육각형 육목 (HeXO 엔트리판) — 설계

원본: [HeXO](https://hexo.did.science/) (WolverinDEV, 오픈소스, 바이브코딩). 규칙을 빌리되
**동일 구현이 목적이 아니다** — 엔트리 런타임에 맞춰 재구성한다.

Entry Online 확장(`extensions/Entry Online`)으로 1:1 온라인 대전을 지원하고, 확장이 없어도
로컬 플레이는 그대로 돌아간다.

## 0. 원본에서 가져오는 것 / 바꾸는 것

**그대로 가져온다 (게임의 정체성)**

| 항목 | 내용 |
| --- | --- |
| 판 | 육각 격자(pointy-top) |
| 승리 | 3축 중 하나에 자기 돌 6개 연속 |
| 오프닝 균형 | **선공 첫 턴만 1개**, 이후 양쪽 매 턴 2개씩 (Connect6 계열 공정 규칙) |
| 색 | 노랑(선공) / 파랑(후공) |
| 인원 | 1:1 |

**바꾼다 (엔트리 최적화)**

| 원본 | 엔트리판 | 이유 |
| --- | --- | --- |
| 무한 보드 + 드래그·줌 스크롤 | **고정 벌집 판 13열 × 11행 = 143칸** | 엔트리는 매 프레임 재배치가 비싸다. 판을 배경 이미지 **1장**으로 고정하면 렌더 비용이 0이 된다 |
| 마우스 클릭 착수 | **방향키 커서 + 스페이스 착수** | 픽셀→육각셀 역변환은 블록으로 비싸고 부정확. 커서는 정수 덧셈만 쓴다 |
| 8칸 근접 제한 | **삭제** | 유한 판이 같은 역할(무한 확산 방지)을 한다. 규칙 하나를 없애면 검증 블록 수십 개가 사라진다 |
| 레이팅·토너먼트·관전·시계 | 없음 | 범위 밖 |
| 무제한 되돌리기 | 턴 내 1회 무르기(선택) | |

유한 판이라 가장자리가 전략에 들어온다 — 원본과 다른 맛이 되지만, 6목이 성립하는
최소 크기는 확보한다.

## 1. 좌표계 — 설계의 심장

**저장**: 1차원 리스트 `$보드` 143칸. `index = (행-1) × 13 + 열`. 값 `0`=빈칸 · `1`=노랑 · `2`=파랑.

**배치**: pointy-top, **odd-r offset**(홀수 행이 반 칸 오른쪽).

**화면 변환** (셀 크기 s=13 → 셀 폭 W=√3·s≈22.52, 행 간격 1.5·s=19.5):

```
x = X0 + (열-1) × W + (행 mod 2) × W/2
y = Y0 - (행-1) × 19.5
```

⚠️ `X0`·`Y0` 같은 상수를 이 문서에 적어 두지 않는다 — 판 이미지와 착수 좌표가 갈라지면
반 칸씩 어긋난다. 기하는 `tools/lib/sprite-gen.mjs` 의 **`hexLayout()` 한 곳**에서만 나오고
판 이미지(`hexBoard()`)와 spec 이 함께 쓴다. 실제 좌표는 빌드 타임에 `칸X`·`칸Y` 리스트로
구워 런타임 블록에는 좌표 계산이 아예 없다.

판 전체 = 폭 304 · 높이 221 → 480×270 무대에서 좌우로 88px씩 남고, 위아래에 차례 표시와
조작 안내가 들어간다.

**방향키**: `←→` 열 ±1 · `↑↓` 행 ±1. 순수 정수 연산이고 모든 칸에 도달한다.
화면상 `↑`는 반 칸 대각으로 보이지만 벌집판에서는 이게 자연스러운 "위".

**승리 3축** (odd-r 이웃 공식 — 직접 유도, 부호 주의):

| 축 | 다음 칸 |
| --- | --- |
| 가로 E | `(행, 열+1)` |
| 우하 SE | `(행+1, 열 + (행 mod 2))` |
| 좌하 SW | `(행+1, 열 - 1 + (행 mod 2))` |

**승리 판정은 방금 놓은 돌에서만** 3축 × 양방향 5칸 = 최대 30회 조회로 끝낸다.
판 전체 스캔(143칸 × 3축)은 금지 — 엔트리에서 눈에 띄게 느려진다.

스캔 중에는 `행`·`열`을 따로 들고 다니다가 보드를 읽을 때만 index로 합친다.
index 증분(`+1`, `+13+행mod2`)으로 걷는 방식은 열 넘침(13열 → 다음 행 1열) 오판을 만든다.

## 2. 장면 구성

| 장면 | 내용 |
| --- | --- |
| `로비` | 로고 · [로컬 플레이] · [온라인 플레이 🔒] · 확장 상태 표시 |
| `대기` | (온라인 전용, **Phase 2**) "상대를 찾는 중" · 취소 |
| `게임` | 판 · 커서 · HUD(턴/남은 돌/닉네임) |
| `결과` | 승/패/무 · 다시하기 → 로비 |

`결과 → 로비` 재진입 루프가 있으므로 로비 오브젝트는 **dualStart**(`when_run` + `when_scene_start`)로
건다. 엔트리의 시작 이벤트는 **현재 장면 오브젝트에만** 발화하므로
([engine.js:662](../../../../../upstream/entryjs/src/class/engine.js) → container `mapEntityIncludeCloneOnScene`),
다른 장면에 시작 블록을 두면 조용히 죽은 코드가 된다.

## 3. 로비 잠금 — 확장 감지

```
$확장프로그램 == 0  →  [온라인 플레이] 회색 + 자물쇠 + "확장 프로그램이 필요합니다"
$확장프로그램 != 0  →  컬러 + 클릭 가능
```

확장이 125ms마다 이 값을 다시 쓰므로 **계속 폴링**한다. 설치 후 페이지를 새로고침하면
버튼이 저절로 풀린다. 값 `-1`은 Pro 모드 정원 초과 신호라 방 모드에서는 안 나오지만,
`!= 0` 판정이면 어느 쪽이든 안전하다.

## 4. 온라인 흐름

```
[온라인 플레이] → $입장("<Entry Online 계정 ID>") → 장면:대기
    → $유저번호 != 0 대기        (취소 → $나가기 → 로비)
    → 내슬롯 = $유저번호          (1 = 노랑·선공 / 2 = 파랑·후공)
    → 장면:게임
```

- 등록 정원 **2**, 방 모드(Pro 불필요).
- **취소 버튼은 필수다.** 상대가 없으면 방이 잠기지 않아 영원히 대기한다 —
  참조 샘플(실시간 줄다리기)이 그대로 걸려 있는 빈틈이다.
- **이탈 감지**: `$유저연결상태`의 상대 슬롯이 `"끊김"`이 되면 "상대가 나갔습니다" → 승리 처리.
- 재시작은 `$나가기` 후 로비 복귀. 같은 방 재사용은 하지 않는다.

## 5. 동기화 변수와 쓰기 소유권

**철칙: 지금 턴인 플레이어만 게임 상태를 쓴다.** 턴을 넘기는 순간 쓰기 권한도 넘어간다.
동시에 같은 키를 쓰는 상황이 생기지 않으므로 LWW 충돌이 구조적으로 0이 된다.

| 이름 | 종류 | 쓰는 주체 |
| --- | --- | --- |
| `$보드` | 리스트 143 | 현재 턴 플레이어 |
| `$턴` | 변수 (1/2) | 턴을 끝내는 플레이어가 상대로 넘김 |
| `$남은돌` | 변수 | 현재 턴 플레이어 |
| `$최근수1` `$최근수2` | 변수 | 현재 턴 플레이어 (마지막 착수 표시용) |
| `$승자` | 변수 (0/1/2/3=무) | 승리를 확정한 플레이어 |
| `$수순` | 변수 | 턴 카운터, 단조 증가 |
| `$닉네임1` `$닉네임2` | 변수 2개 | **각자 자기 것만** |
| `$확장프로그램` `$유저번호` `$방인원수` `$유저연결상태` | 예약 | 확장이 씀 |

닉네임을 **리스트가 아니라 변수 2개**로 쪼개는 이유: 동기화 단위가 리스트 전체라
서로 다른 인덱스를 써도 동시 쓰기면 한쪽이 유실된다
([roomManager.js:313](../../../../entry-online/src/realtime/roomManager.js)). 샘플에서 실제로 발생 가능한 경합이다.

**`$`를 붙이면 안 되는 것** (각자 로컬): `커서행` · `커서열` · `내슬롯` · `모드` · `깜빡임` ·
입력 상태. 실수로 `$`를 붙이면 8Hz로 상대에게 방송된다.

## 6. 로컬/온라인 단일 코드 경로

두 모드의 차이는 **"지금 내가 놓을 수 있나?"** 한 줄뿐이다.

| 모드 | 조작 가능 조건 |
| --- | --- |
| 온라인 | `$턴 == 내슬롯` |
| 로컬 | 항상 참 (`내슬롯`을 매 턴 `$턴`으로 갱신 = 핫싯) |

로컬 모드에서도 `$` 변수를 그대로 쓴다. 방에 입장하지 않았으면 확장이 아예 송신하지 않으므로
(`extensions/Entry Online/EO/inject.js:241` 의 `pollChanges` 가 `sessionActive` 가 아니면 조기 반환) 무해하다.
덕분에 **판·착수·승리 판정 로직을 한 벌만 만들면 된다.**

## 7. 오브젝트 예산

| 오브젝트 | 수 | 비고 |
| --- | --- | --- |
| 벌집 판 배경 | 1 | 생성 SVG 1장, 스크립트 없음 |
| 돌 | 1 + 클론 ≤ 143 | 클론 한도 360 ([init.js:63](../../../../../upstream/entryjs/src/util/init.js)) |
| 커서 | 1 | 깜빡임만 |
| HUD 글상자 | 4~6 | 턴 · 남은 돌 · 닉네임 ×2 · 안내 |
| 로비 UI | 5~7 | 로고 · 버튼 2 · 자물쇠 · 안내문 |

**매 프레임 갱신하는 것이 없다.** 판은 정적 이미지, 돌은 놓을 때만 클론 1개 생성,
커서는 키 입력 때만 이동. 이게 "엔트리는 느리다"를 우회하는 핵심이다.

## 8. 조작

| 입력 | 동작 |
| --- | --- |
| `← → ↑ ↓` | 커서 1칸 이동. 누르고 있으면 반복(`is_press_some_key` 폴링 + 0.11초 간격) |
| `스페이스` | 착수 — 빈 칸 · 내 턴일 때만. **누른 순간 1회**(연타·키 반복 방지 에지 검출) |
| `Z` (선택) | 이번 턴 첫 돌 무르기 |

선공 첫 수는 **중앙 자동 착수**로 처리한다(원본 규칙: 중앙 1개). 규칙이자 튜토리얼 역할.

## 9. 승리·종료

- 착수할 때마다 그 돌 기준 3축 스캔 → **6개 이상 연속이면 승리**.
- 한 턴에 2개를 놓으므로 첫 돌에서 이기면 즉시 종료(둘째 돌 안 놓음).
- 판이 가득 차면 무승부.
- 온라인 이탈은 §4.

## 10. 만들기 순서 — 수직 슬라이스

| Phase | 내용 | 완료 기준 | 상태 |
| --- | --- | --- | --- |
| 1 | **로컬 플레이 완성** — 판·커서·착수·2개 턴·승리 판정·결과 | L1~L4 전부 통과, 헤드리스 봇이 6목 완성 | ✅ 2026-08-15 (`hexo_004.ent`, verify 38/38) |
| 2 | 온라인 입장·대기 장면·슬롯 분기 | 상대 대기/취소 동작 | ✅ 2026-08-15 (`hexo_007.ent`) |
| 3 | 동기화 렌더 + 이탈 처리 | 상대 착수가 내 화면에 그려짐 | ✅ 헤드리스 시뮬 통과 · ⬜ devtools 2창 실검증 |
| 4 | 연출 — 최근 수 표시, 승리 라인 강조, 효과음 | | ⬜ |

**Phase 2~3 에서 정해진 것**

- `$입장` 인자는 spec 최상단 `EO_OWNER_ID` **상수 한 줄**로 뺐다(기본값 `change_me`).
  편집기에서 고치려면 `대기` 장면 → `안내` 오브젝트의 `$입장( … )` 블록 글자를 바꾼다.
- **판을 세우는 쪽은 선공(슬롯 1) 하나뿐**이다. 후공까지 초기화하면 상대 판을 지운다.
  후공은 "판 위의 돌이 정확히 1개" 가 될 때까지 기다렸다 시작한다 — 수순 같은 카운터는
  지난 대국 값이 남아 있어 앞질러 시작한다.
- **그리는 주체도 하나뿐**이다. 내 돌·상대 돌을 가리지 않고 렌더러(`draw`)가 `$보드` 와
  `그린판`(화면 사본)의 차이만큼 그린다. 패치를 한 번 놓쳐도 다음 패스가 메운다.
- `$나가기` 는 **인자 없는 함수**로 만들었다(실제 확장 계약과 동일, 로드·실행 확인).

Phase 1이 끝난 지금 **확장 없이도 완성된 게임**이다. 로비의 확장 잠금 표시까지 들어가 있고,
온라인은 그 위에 얹는다.

## 11-1. 실제로 밟은 함정

- **글상자에 효과 블록을 걸면 스레드가 죽는다.** 엔트리가 `entity.effect` 를 sprite 에만
  초기화한다(`entity.js:42-48`). 잠김 버튼을 반투명으로 만들려다 로비 전체가 멈췄다 →
  버튼 오브젝트 2개의 show/hide 로 바꿨다. 정본: [knowledge/07](../../../knowledge/07-runtime-quirks.md).
- **가로축만 검증하면 패리티 버그를 못 잡는다.** E/W 는 행이 안 바뀌어 odd-r 보정을 타지
  않는다. 대각축(SE) 대국을 검증에 따로 넣었다.
- **이웃표는 빌드 타임에 기하로 검증한다.** 이웃이라 주장하는 두 칸의 중심 거리가 셀 폭과
  같은지, 반대 방향이 서로를 가리키는지 spec 로드 시 단언한다. 부호 하나 틀려도 즉시 잡힌다.
- **장면 재진입 시 다른 오브젝트가 지난 판의 값을 먼저 읽는다.** 진행 오브젝트가 지난 판의
  `$승자` 를 보고 1.3 초 뒤 결과 장면으로 튀어 두 번째 대국이 저절로 끝났다. 오브젝트 간
  실행 순서는 지정할 수 없으므로 **장면이 바뀌기 전에**(`resetGame()`) 지운다.
  1.3 초 지연 탓에 짧은 판은 우연히 통과한다 — Phase 1 검증이 통과한 것도 운이었다.
  정본: [knowledge/07](../../../knowledge/07-runtime-quirks.md).
- **한 프레임에 만든 클론들이 전역을 읽으면 한 자리에 겹친다.** 상대 턴의 돌 2~3 개가
  한 번에 도착하는 온라인에서 바로 드러난다. 클론 **개수는 맞고 화면만 틀려서** 좌표
  집합의 크기를 세는 가드가 필요하다. 해결은 템플릿을 목표 상태로 맞춘 뒤 복제(상속).

## 12. 검증 계획

| 레이어 | 방법 |
| --- | --- |
| L1~L3 | 기존 사다리 그대로 |
