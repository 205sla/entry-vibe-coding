# RPG 작품 사례: 가상 맵, 클론 배치, 대화와 저장 경계

[지식 인덱스](README.md) · [블록 및 설계 패턴](04-script-and-blocks.md) · [구조 증거 JSON](evidence/rpg-remake.json)

분석 대상은 사용자 제공 **엔트리 최대규모 RPG게임의 리메이크.ent**다. “최대규모”는 작품 이름이며 다른 작품과 비교해 검증한 순위가 아니다. 대사·이미지·음악을 옮기지 않고 실제 블록에서 확인한 설계와 새 작품에 적용할 조건을 정리한다.

- 분석일: 2026-09-10. 원본 크기: **214,417,286 bytes**.
- SHA-256: `b5e27e8e97c59c367b7c2ff0a79197c0b3c2af9d7742a004fdbe3bd423582ba3`.
- gzip을 스트리밍 해제하고 TAR의 `temp/project.json`만 메모리에 보관했다. JSON 크기는 19,638,838 bytes다. 원본이나 에셋을 저장소로 복사하지 않았다.
- 범위는 **정적 구조 분석**이다. 편집기 로드, 플레이, 프레임 속도, 저장 후 재실행은 검증하지 않았다. “관찰”은 코드 사실이며 “해석”과 “재사용 제안”은 구분한다.
- 경로는 JSON Pointer다. `objects[*].script`와 `functions[*].content` 문자열을 JSON 파싱한 뒤 해석한다. ID와 경로를 함께 기록해 이름 변경과 배열 순서 변경을 구분한다.

## 1. 실제 장면과 월드의 맵 번호를 분리한다

**관찰.** 전역 변수 `sfbe`(> 장면 번호 <, `/variables/245`)는 실제 scene ID와 별개다. 탐험 렌더러 `4smj`(`/objects/90`)는 실제 장면 `9hgw`에 속하지만, scene-start 스택에서 sfbe=22, 23 등의 조건에 따라 다른 배치를 만든다. `/objects/90/script/0/2`는 sfbe=22 분기이며 그 안에 공통 배치 함수 `func_w6x3` 호출이 있다. 이 객체는 모양 156개를 가지며 script 길이가 1,198,666문자다. 이는 JS 문자열 길이이며 UTF-8 bytes가 아니다.

불러오기 객체 `8vs4`(`/objects/13/script/0/4`)는 개인저장 첫 슬롯을 sfbe에 대입하고 같은 스택 끝 `/objects/13/script/0/41`에서 탐험 장면으로 이동한다. 전환 연출 객체 `7vq5`도 `/objects/32/script/2/1/statements/0/6`에서 `start_scene(9hgw)`를 호출한다.

**해석.** 실제 장면은 탐험·전투·메뉴 같은 실행 모드를 나누고, sfbe는 탐험 안의 지역을 선택한다. 따라서 실제 장면 20개를 “맵 20개”로 해석하면 안 된다. 비교 상수만 세어 방문 가능한 맵 총수를 확정하는 것도 부정확하다.

**재사용 제안.** `modeScene`, `mapId`, `storyStep`을 별도 상태로 둔다. 이동 전에 mapId·도착좌표를 확정하고, scene-start 렌더러는 이를 읽기만 하게 한다. spec의 맵별 데이터에서 배치 코드를 생성하면 큰 조건 트리를 손으로 유지할 필요가 줄어든다.

**비용과 확인점.** 공통 렌더러를 공유하는 대신 조건 분기가 집중된다. 모든 지역·되돌아가기·저장 복귀를 따로 검사해야 한다. [장면 재진입 초기화 순서](07-runtime-quirks.md#장면을-다시-들어가면-when_scene_start-들이-지난-판의-값을-먼저-읽는다)도 적용 대상이다.

## 2. 모양·크기·좌표를 정한 뒤 복제하는 공통 배치 함수

**관찰.** 함수 `w6x3`(`/functions/21`)는 모양번호, 크기, X, Y, 밝기, 반전 정보를 받는다. 본문 `/functions/21/content/0/0/statements/0`은 반전 문자열의 첫째·둘째 문자가 1이면 각각 flip_y·flip_x를 실행한다. 모양·크기가 `=`이면 변경을 생략한다. 이어 locate_xy → brightness 변경 → create_clone(self)가 배치되며 복제는 본문 6번 블록이다. 이 함수 호출 노드는 작품 전체에 **1,549개** 있다. 동시에 존재하는 클론 수가 아니다.

배치 대상 `4smj`의 clone-start 스택 `/objects/90/script/1`은 show를 실행하고 일부 picture_index에만 회전 애니메이션을 붙인다.

**해석.** 배경·소품을 같은 생성 계약으로 배치하며 스폰 시 시각 상태와 생성 후 행동을 분리한다. 속성을 먼저 정하고 복제하는 순서는 [클론 엔티티 상속](07-runtime-quirks.md#회피-패턴-2--엔티티-상속으로-넘기기-자리모양이-목적일-때)과 맞는다.

**재사용 제안.** spec에 `{shape, scale, x, y, brightness, flipX, flipY}` 레코드를 두고 하나의 helper로 변환한다. 동적인 상태는 생성 후 객체 전용 변수로 처리하고 정적인 좌표·모양은 복제 전에 설정한다.

**비용과 확인점.** `=`는 앞선 template 상태를 이어받는 표식이므로 완전히 독립된 배치 레코드가 아니다. flip도 절대값 설정이 아니라 토글이다. 같은 입력을 두 번 실행해도 같은 결과가 된다고 가정하면 안 된다. 반전 문자열은 최소 두 글자여야 한다. 새 helper는 매 레코드의 완전한 상태를 지정하거나 이전 반전 상태와 비교해 필요한 토글만 실행하도록 설계한다.

## 3. 타자기 대화의 완료 입력과 다음 대사 입력을 분리한다

**관찰.** 함수 `at4g`(`/functions/3`)의 지역변수는 입력수와 클릭수다. 본문은 글상자를 비운 뒤 문자를 하나씩 추가한다. 진입 시 클릭 또는 Space가 이미 눌려 있으면 클릭수=1로 기록하고, 손을 떼면 0으로 바꾼다. 새 입력을 감지하면 2로 바꾸어 타자기 반복을 종료한다. 이후 전문을 text_write한 다음 **입력 해제 대기 → 넘기기 안내 메시지 → 새 입력 대기 → 안내 닫기 메시지** 순서로 진행한다.

근거는 `/functions/3/content/0/0/statements/0`의 제어 순서와 `/functions/3/localVariables`다. 함수 호출은 **818개**다. 대화 내용은 별도 함수 `8ec4`, `z7b5`, `ezfv`에서 번호 구간으로 나뉜다(`/functions/29`, `/functions/30`, `/functions/43`).

**해석.** “현재 문장을 즉시 완성”하는 클릭이 다음 문장까지 넘어가는 현상을 막으려는 입력 경계 처리다. 모든 입력 타이밍에서 성공한다는 뜻은 아니다.

**재사용 제안.** 대화 상태를 `typing → waitingForRelease → waitingForAdvance`로 명시하고 UI와 입력 처리를 한 소유자에게 모은다. 진입 전부터 누르기, 입력 도중 길게 누르기, 빠른 두 번 클릭, Space와 포인터 교대를 검증한다.

**비용과 확인점.** 타자기 안에는 길이 반복과 5회 반복이 들어 있다. 숫자를 밀리초나 문자당 고정 시간으로 읽으면 안 된다([반복 블록의 틱](07-runtime-quirks.md#반복하기-블록--1-프레임반복-60fps-암묵-틱)). 여러 대화 호출이 동시에 같은 글상자를 갱신하지 않도록 소유권도 필요하다.

## 4. 몬스터는 클론의 개별 상태와 공유 리스트를 함께 쓴다

**관찰.** 몬스터 `s6lj`(`/objects/179`)에는 객체 전용 변수 10개가 연결된다. `pont`(복제본인가), `0xez`(고유번호), `9pjw`(종류 번호), `qpjn`(상태) 등이 있다. 전역과 구분되는 스코프의 의미는 [오브젝트 전용 변수와 클론별 상태](04-script-and-blocks.md#오브젝트-전용-변수와-클론별-상태)를 따른다.

초기화 스택 `/objects/179/script/3`의 순서는 다음과 같다.

1. pont=10으로 복제본 표시.
2. 공유 생성 수 `74jw`를 늘리고 0xez에 고유번호 저장.
3. x·y·체력을 각각 `tc34`, `qzgy`, `lqmi` 리스트에 추가.
4. 생성 메시지를 보낸 뒤 위치 리스트를 갱신하는 반복 실행.

공격 메시지 스택 `/objects/179/script/5`는 복제본인지 확인하고 충돌한 몬스터의 lqmi[0xez]에서 공격력을 뺀다. 생성 메시지 스택 `/objects/179/script/13`은 **pont=0인 원본만** 종류 번호를 지정하고 create_clone(self)를 호출한다. 메시지를 받는 클론의 재복제를 제한하는 명시적 가드다.

**해석.** 클론은 충돌·이동을 맡고 공유 리스트는 외부에서 몬스터 상태에 접근하는 색인 역할을 한다. 방향을 ID로 재사용하는 우회 방식만 가능한 것은 아니다.

**재사용 제안.** 개별 쿨다운·이동상태는 객체 전용 변수, HP·타겟 위치 등 다른 객체가 조회할 값은 고유 ID 기반 리스트로 구분한다. 스폰 수신부에 원본/클론 가드를 두고 ID별 리스트 길이와 생존 상태를 검증한다.

**비용과 확인점.** 이 객체에는 clone-start 스택이 **8개**다. 일부는 0.05초·0.1초 대기 또는 고유번호가 0이 아닐 때까지 대기를 사용한다. 이것만으로 초기화 순서나 원자성이 보장되지는 않는다. 새 구현에서는 ID 할당·리스트 초기화·준비 완료를 한 경로에서 끝내고 나머지 처리가 준비 플래그를 기다리게 한다. [다중 clone-start race](07-runtime-quirks.md#다중-when_clone_start-스크립트는-병렬-실행--클론-초기화-race)와 [메시지 fan-out](07-runtime-quirks.md#when_message-핸들러는-클론에도-살아-있음--fan-out-spawn)이 관련 정본이다.

## 5. 체크포인트, 저장 레코드, 외부 저장 기능은 서로 다르다

**관찰.** `sle7`(`/functions/25`)는 체크포인트 위치 `w271`와 세부 위치 `bg79`를 기록한다. 이는 게임 상태의 갱신이다. 별도 `apj8`(`/functions/51`)는 **@확장프로그램 변수 x0b2=1일 때만** 중간저장 반복을 시작한다. 대기 상태가 풀린 뒤 개인저장 리스트 `bph8`에 mapId, 좌표, 캐릭터, 스토리, 재화 등을 쓴다. 원본의 이 리스트는 21슬롯이다. 마지막에는 `func_55bo`를 호출한다.

그러나 `55bo`(`/functions/48`, 표시 이름 @저장)의 함수 정의에는 실행 본문이 없다. `/functions/48/content/0/0/statements`는 `[[]]`다. 저장 UI 연출과 목록 수정이 있어도 원본 JSON만으로 브라우저 밖 영속저장을 증명할 수 없다. 이름의 @ 표기도 외부 서비스의 구현·가용성을 증명하지 않는다.

값 함수 `xj7m`(`/functions/49`)과 수정 함수 `uopi`(`/functions/50`)는 한 리스트 항목 안의 문자열을 `&번호#` 경계로 나눈다. 읽기는 다음 경계를 찾고 substring으로 값을 꺼낸다. 쓰기는 앞부분+새 값+뒷부분을 결합해 리스트 항목을 교체한다. 일부 리스트 상태는 이렇게 문자열로 묶인다.

**해석.** 체크포인트는 복귀 기준, bph8은 직렬화할 상태, @저장은 외부 연결 지점으로 읽는 것이 타당하다. 외부 저장이 실제 연결되었는지는 확인하지 않았다.

**재사용 제안.** `captureState → encode(version) → persist → acknowledge`를 별도 계약으로 둔다. 연결 구현이 없으면 저장 완료를 표시하지 않는다. 고정 길이 플래그열과 구분자 문자열을 쓰려면 버전, 슬롯 범위, 경계 표식, 데이터 타입을 검사하고 초기값·이전 버전·손상된 레코드 정책을 정한다.

**비용과 확인점.** 읽기 함수의 다음 구분자 존재 검사만으로 모든 시작 경계·인덱스가 유효해지는 것은 아니다. 수정 함수도 연속 경계를 전제로 substring을 수행한다. 구분자가 값 안에 들어오는 문제와 빈 값도 고려해야 한다. [문자열 범위 예외](07-runtime-quirks.md#char_at--substring-은-범위를-벗어나면-throw--문자열-타일맵에-가드-필수)를 피하도록 디코딩 전에 순차 검사를 둔다. 영속성은 저장 호출 직후 목록 비교가 아니라 앱을 닫고 다시 연 뒤 상태 복원까지 확인한다.

## 6. 카메라 효과는 초기 위치를 기준으로 계산한다

**관찰.** 함수 `ozj7`(`/functions/11`)은 호출 시 self.x를 함수 지역변수에 보관한다. 이후 반복에서 `x = initialX - playerX × ratio/100`을 locate_x로 적용한다. player는 전투 캐릭터 `90lj`다. 호출 예는 `/objects/202/script/2/1`의 ratio=9와 `/objects/217/script/1/1`의 ratio=5다.

**해석.** 배경마다 비율을 달리한 시차 스크롤 형태다. 매번 현재 x에서 이동량을 빼는 누적 방식과 달리 저장한 초기 위치에서 다시 계산한다.

**재사용 제안.** 화면 좌표를 `worldX - cameraX × parallax`로 유도하고 초기 배치값과 화면 좌표를 구분한다. 장면 재진입 때 초기 위치를 다시 잡는다.

**비용과 확인점.** 이 함수에는 무한 반복이 있으므로 유한한 보조 함수처럼 호출 뒤 코드가 곧 실행된다고 가정하면 안 된다. 이미 변환된 좌표에서 초기 x를 다시 캡처하면 원점이 달라질 수 있다. 캐릭터·맵 변경 때 재진입 시나리오로 확인한다.

## 새 RPG를 만들 때 가져갈 설계와 검증

| 가져갈 설계 | 새 구현에서 확인할 조건 |
|---|---|
| 실행 모드와 mapId 분리 | 이동 전 상태 확정, 지도별 진입·재진입·저장 복귀 |
| 공통 배치 함수 | 모든 속성 명시, 반전 토글 누적 방지, 클론 수 상한 |
| 대화 release/press 경계 | 길게 누르기·연타·입력 수단 교대, 대화 단일 소유자 |
| 객체 전용 상태 + 공유 리스트 | 초기화 완료 이후 조회, ID 범위와 리스트 길이 일치 |
| 버전 있는 저장 레코드 | 저장 어댑터 연결 여부와 재시작 후 복원 확인 |
| 초기좌표 기반 시차 | 원점 재설정, 카메라 좌표와 캐릭터 좌표 구분 |

이 사례에서 새 엔진 불변 동작이나 해결된 버그를 발견했다고 주장하지 않는다. 대기 시간에 의존하는 동기화, 상태를 생략하는 배치 레코드, 빈 외부 저장 함수를 그대로 제작 권장 패턴으로 복사하지 않는다.
