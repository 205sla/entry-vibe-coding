# 3D 작품 사례 — 정육면체 회전·직교투영·면 조명

사용자가 제공한 **3D의 리메이크.ent**를 2026-09-10에 정적으로 분석했다. 이 파일에서 확인한 핵심은 마우스로 회전시키는 정육면체 렌더러다. 제목과 사용자 분류는 3D 게임이지만, 코드에서 이동·충돌·목표·승패 규칙은 확인되지 않았다. **직교투영한 면을 붓으로 채우는 방식**이며 레이캐스팅·원근투영 방식은 아니다.

원본은 수정하거나 저장소에 복사하지 않았다. [검증용 근거 JSON](evidence/3d-remake.json)은 원본 SHA256, 구조 통계, 핵심 배열·블록 경로·수식 계수를 보관한다. 첨부 파일의 이름·주석 등은 분석 데이터로만 취급했다.

- SHA256: `51c92993cbc54103c8f3877682e3560c9f0616331d3d0eb0785df7634810bb81`
- 압축 파일: 140,508 bytes. gzip 해제 후 `temp/project.json`: 191,953 bytes.
- 경로 표기: `objects[*].script`, `functions[*].content` 문자열을 JSON.parse한 뒤의 **0부터 시작하는 JSON pointer**다. 엔트리 리스트의 항목 번호는 **1부터 시작**한다.
- 검증 범위: 압축·JSON 구조, 블록 참조, 수식 해석, 회전 수학 교차검증. 편집기 실행·마우스 실제 조작·픽셀·FPS는 검증하지 않았다.

## 1. 꼭짓점과 법선을 같은 좌표 배열로 회전

**관찰.** 소문자 리스트 `x/rztd`, `y/bhkh`, `z/0l2z`는 각각 11개 항목이다. 1~8은 모든 ±1 조합의 정육면체 꼭짓점, 9~11은 `(1,0,0), (0,1,0), (0,0,1)`이다. 대문자 `X/ox7h`, `Y/d48u`, `Z/85cr`는 같은 길이의 계산 버퍼다. 회전 루프는 11회 반복하고 `direction`을 0에서 시작해 1씩 증가시키며 인덱스로 쓴다.

근거: `/variables/12/array`~`/variables/14/array`, `/objects/1/script/0/12/statements/0/7`(블록 `7wdb`).

**해석.** 위치와 방향 벡터를 같은 회전으로 갱신해 면 판정에 필요한 법선을 함께 유지한다. 이동이 없으므로 두 종류에 같은 연산을 써도 된다.

**재사용 제안.** 작은 고정 메시에는 이 배열 배치가 단순하다. 일반화할 때는 원본 꼭짓점·변환 결과·면 인덱스·법선을 구분하고, **평행이동을 법선에 더하지 않는다**. 이름이 같은 스칼라 `x/avtm`, 리스트 `x/rztd`, 스칼라 `L/gkw7`, 리스트 `L/7k28`가 공존하므로 이름만으로 연결하지 말고 ID를 사용한다.

## 2. 두 축 회전과 직교투영

**관찰.** `리스트/z68k`는 `[cos(a), cos(b), sin(a), sin(b)]`를 저장한다. 입력 오브젝트의 x·y 위치는 화면상의 물체 위치가 아니라 각속도 `x+, y+`를 삼각함수에 전달하는 임시 저장소다. a·b는 엔트리 삼각함수에 전달되는 도 단위 회전량이다. 각 벡터를 다음 순서로 계산한다.

```text
Y  = y*cos(a) - z*sin(a)
Tz = y*sin(a) + z*cos(a)
X  = x*cos(b) + Tz*sin(b)
Z  = Tz*cos(b) - x*sin(b)
(x,y,z) ← (X,Y,Z)
화면 좌표 = (50*X, 50*Y)
```

근거: 블록 `gktu, wlpe, h5ie, hm6d`는 `/objects/1/script/0/12/statements/0/7/statements/0/1`~`/4`. 투영 예는 `/objects/2/script/0/1/statements/0/4/statements/0/2`의 `7tpj`다.

**해석.** x축 회전 후 y축 회전이며, 깊이로 나누거나 카메라 위치를 빼는 연산은 없다. 고정된 시선에 대해 물체를 회전시키는 **직교투영**이다. 축척 50은 정면에서 변 길이 100의 큐브를 만든다. 여섯 면 각각에 `start_fill/stop_fill` 쌍이 있으므로 와이어프레임 전용도 아니다.

**재사용 제안.** 모델 뷰어·퍼즐용 미니 렌더러에 적합하다. 원근 카메라가 필요하면 별도로 시점 변환·깊이 나눗셈·근평면 처리를 설계해야 한다. 매번 변환 결과를 원본 배열에 다시 쓰므로 장시간 부동소수점 오차가 쌓일 수 있다. 큰 모델은 불변 모델 좌표와 회전 상태를 따로 보관하는 편이 검증하기 쉽다.

**수학 검증.** 원본 네 대입 블록의 AST를 읽어 숫자·리스트 참조·사칙 연산을 평가했다. `(a,b)=(0,0), v=(1,1,1)`은 그대로 유지되고, `(90,0), v=(0,1,0)`은 약 `(0,0,1)`이 된다. `(30,-20), v=(1,-1,1)` 결과는 `(0.81450456,-1.36602540,0.68597151)`이며 제곱 길이는 3으로 보존됐다. 이는 수식 검증이며 엔트리 실행 검증이 아니다. 입력·출력은 근거 JSON의 `mathChecks`에 기록했다.

## 3. 깊이 정렬 대신 마주 보는 면 중 하나 선택

**관찰.** 렌더러는 다음 조건의 참·거짓 분기에서 각 면 하나를 채운다. 마지막 항목은 닫기 위해 시작점을 반복한다.

| 검사 | 참 분기 꼭짓점 | 거짓 분기 꼭짓점 |
|---|---|---|
| `z[9]<0` | 1→2→4→3→1 | 5→6→8→7→5 |
| `z[10]<0` | 1→2→6→5→1 | 3→4→8→7→3 |
| `z[11]<0` | 1→3→7→5→1 | 2→4→8→6→2 |

근거: `/objects/2/script/0/1/statements/0/4`~`/6`, 블록 `z5ty, rexo, 1nwi`. 각 면에서 시작점으로 이동한 뒤 fill을 켜고 나머지 꼭짓점으로 이동한다.

**해석.** 세 쌍의 반대 면에서 카메라 쪽 한 면씩 선택하는 정육면체 전용 가림 처리다. 깊이 버퍼나 거리 정렬 목록은 없다. 정확히 옆으로 선 면도 거짓 분기에서 선택되지만 직교투영에서는 폭이 0이 된다.

**재사용 제안.** 단일 볼록 큐브에는 이 선택법을 사용할 수 있다. 여러 물체·오목 메시·교차하는 면으로 확장할 때는 이 분기만으로 가림이 해결되지 않는다. 면 정렬이나 깊이 버퍼가 필요한지 별도로 결정하고, 면 연결은 코드 반복 대신 데이터로 옮긴다.

## 4. 내적과 바닥 광량으로 면별 명암

**관찰.** 광원 리스트 `L/7k28`의 초기값은 약 `(0.57735026919,0.57735026919,-0.57735026919)`다. 면마다 회전된 법선과 L의 내적을 구하고, 반대 면에서는 부호를 뒤집는다. 광량을 `round(255 * func_rq1f(0.1, dot))`로 구해 R·G·B에 같은 값으로 전달한다.

함수 `rq1f`는 두 인자의 큰 값을 선택한 뒤 1보다 크면 1로 바꾼다. 따라서 활성 면 렌더 경로는 `round(255 * min(1,max(0.1,dot)))`다. 이름이 max여도 일반적인 max 함수와 같지 않다.

근거: `/variables/8/array`, 블록 `xclx`(`/objects/2/script/0/1/statements/0/4/statements/0/0`), `/functions/0/content/0/0/statements/0`의 `r916, 6iv4`.

**해석.** 고정 방향 조명과 법선 내적을 쓰는 단순한 확산 반사 형태에 최소 광량 0.1을 준 것이다. 그림자 투사·텍스처·정반사 계산은 없다.

**재사용 제안.** 함수 이름은 `clampBrightness`처럼 실제 계약을 표현하고, 광원·법선 길이와 밝기 범위를 검사한다. `P/gkig` 리스트를 계산하는 세 대입도 있으나 이를 읽는 곳은 시작 이벤트에 연결되지 않은 분리 표현식 `sbm7`뿐이다. **활성 조명 경로를 P 기반으로 설명하면 틀린다.** 재사용 시 사용되지 않는 계산을 먼저 분리한다.

## 5. 드래그 차분으로 각속도를 더하고 감쇠

**관찰.** 마우스가 눌렸을 때 `x+ += 0.1*(mouseY-prevY)`, `y+ += -0.1*(mouseX-prevX)`를 실행한다. 이후 회전하고 두 값을 각각 0.9배로 줄이며 현재 마우스를 이전 좌표로 저장한다. 키 입력·충돌 감지 블록은 없고 카메라 이동 좌표도 없다.

근거: `/objects/1/script/0/12/statements/0/0`(`8can`), 내부 `ynm6, hn0u`; 같은 반복의 `/8`, `/9`는 `0t4b, 1bri`다.

**해석.** 드래그 양을 각속도에 누적해 놓은 뒤에도 회전이 감쇠하는 관성 조작이다. 초기 상태에는 x+, y+가 0이다.

**재사용 제안.** 감도·감쇠·최대 각속도를 상수로 분리한다. 프레임 시간 보정은 없으므로 현재 계수만으로 기기별 조작 감각이 같다고 보장할 수 없다. 실제 게임으로 확장할 때 이동·충돌·규칙은 별도의 상태로 설계한다.

## 6. 계산 반복의 특수 제어와 렌더 책임 분리

**관찰.** 11개 벡터를 처리하는 초기 반복과 매 프레임 반복은 마지막에 `wait_until_true(boolean_not(continue_repeat))`를 둔다. 매 프레임 회전 루프의 해당 블록은 `jnyz`, 경로는 `/objects/1/script/0/12/statements/0/7/statements/0/8`다. 렌더러는 다른 오브젝트의 독립 `repeat_inf`에서 지우고 다시 그린다.

**해석.** 이미 문서화한 [반복 딜레이 우회 트릭](07-runtime-quirks.md#wait_until_true-조건-속-continue_repeat--반복-딜레이-소멸-동기-루프-트릭)을 쓰는 실물 사례다. 이 작품에 대한 FPS나 동기 실행 시간은 새로 측정하지 않았으므로 기존 사례의 측정치를 이 작품의 성능으로 옮겨 적지 않는다.

**재사용 제안.** 일반 조립으로 만드는 정상 조건식과 구분해야 한다. 이식할 때는 대상 엔진에서 이 스케줄링 의존성을 확인하거나 [값 함수의 동기 처리](07-runtime-quirks.md#함수-호출은-반복하기의-60fps-틱을-우회-꼬리-재귀-최적화) 등 검증된 대안으로 바꾼다. 계산과 렌더가 공유 리스트를 쓰므로 규모가 커질 때는 갱신 완료 신호나 명시적 실행 순서를 두면 중간 상태 읽기를 검사하기 쉽다. 현 파일에서 실제 프레임 찢어짐을 재현했다는 뜻은 아니다.

## 재현과 후속 검증

앱 디렉터리에서 실행한다. 원본 파일은 읽기만 한다.

```powershell
node tools/verify-case-study-evidence.mjs --source 'C:/작품/3D의 리메이크.ent' --evidence knowledge/evidence/3d-remake.json
```

검증기는 원본 해시와 정규화된 JSON pointer의 기대값을 확인한다. 이는 표시 결과·게임 플레이 성공을 보증하지 않는다. 런타임 검증을 추가한다면 드래그 전후 좌표 변경, 마우스를 놓은 뒤 감쇠, 90도 회전에서 면 전환, 그림 삭제 후 재작성, 장시간 벡터 길이 오차를 관찰한다. 여기서 얻은 정육면체 전용 알고리즘을 일반 3D 엔진 계약으로 확대하지 않는다.
