# Entry Online 온라인 대전 작품 만들기

`.ent` 작품을 **Entry Online 확장**(크롬 확장, `wss://online.205.kr/sync`)에 태워 1:1~N인
실시간 대전으로 만드는 법. 확장이 요구하는 계약과, 그 위에서 깨지지 않는 작품 구조.

> 최초 작성: 2026-08-15 (`games/hexo` 1:1 육각 육목 제작에서 도출)

## 언제 읽나

- 온라인 대전 작품을 새로 만들 때 — **먼저 §1 계약을 그대로 베낀다.**
- "상대 돌이 안 보인다 / 판이 지워진다 / 둘 다 시작을 못 한다" → §3
- 서버·확장 없이 온라인 로직을 검증하고 싶을 때 → §4

## 0. 확장이 하는 일은 "공유 메모리" 하나뿐

블록을 추가하지 않는다. 작품이 **정해진 이름의 함수·변수를 미리 만들어 두면** 확장이
거기에 후킹한다(`EO/inject.js` 의 `hookFunctions`). 네트워크 API 가 아니라
**`$` 로 시작하는 변수·리스트가 전 참가자에게 자동 공유되는 것**이 전부다.

작품 쪽 준비물 없이는 아무 일도 일어나지 않는다 — 확장은 없는 변수를 만들어 주지 않고
조용히 무시한다.

## 1. 계약 — 작품이 반드시 갖춰야 할 것

### 1.1 함수 (본문은 **비어 있어야** 한다)

확장이 호출을 가로채는 후킹 지점이라 안이 비는 게 정상이다.

| 표시명 | 파라미터 | 역할 |
| --- | --- | --- |
| `$입장` | 문자 1개 = Entry Online 계정 ID | 방 입장 |
| `$나가기` | 없음 | 퇴장 |
| `$바로시작` | 없음 | 정원이 차기 전 현재 인원으로 시작 |
| `$ai` | 문자 1개 = 프롬프트(100자 이하) | 서버 AI 호출 |

필요한 것만 만들면 된다. `$입장` 인자는 영소문자·숫자·밑줄 3~20자여야 하며, 형식이
틀리면 확장이 `INVALID_OWNER_ID` 로 거부한다.

### 1.2 예약 변수·리스트 (**이름과 종류가 정확해야** 한다)

확장이 약 125ms 마다 값을 덮어써 주는 읽기 전용 값이다. 작품이 여기에 쓰면 곧 지워진다.

| 이름 | 종류 | 값 |
| --- | --- | --- |
| `$확장프로그램` | 변수 | `0` 미설치 · `1` 정상 · `-1` Pro 채널 정원 초과 |
| `$유저번호` | 변수 | 미입장·대기 `0`, 잠긴 방의 내 슬롯 `1..N` |
| `$방인원수` | 변수 | 실제 연결 인원 |
| `$유저연결상태` | **리스트** | 슬롯 순서대로 `"연결"` / `"끊김"` |
| `$ai답변` | 변수 | 마지막 `$ai` 응답 |

### 1.3 DSL 로 만드는 법 — 표시명과 id 를 분리한다

함수 표시명에 `$` 가 들어가야 하는데, DSL 의 기본 표시명은 spec 의 `id` 다. `id: '$입장'`
으로 두면 블록 타입이 `func_$입장` 이 되어 `--check` 의 `/^func_[a-z0-9]+$/i` 에 걸린다
([make-ent.mjs](../tools/make-ent.mjs) `isUserFuncType`). id 는 ASCII 로 두고 **표시명만**
바꾼다 ([spec-dsl.mjs](../tools/lib/spec-dsl.mjs) `fn` 의 `opts.label`).

```js
const fnJoin  = fn.normal('eojoin',  ['eoid'], () => [], [], { label: '$입장' });
const fnLeave = fn.normal('eoleave', [],       () => [], [], { label: '$나가기' });
```

확장은 함수 정의의 `function_field_label` **첫 파라미터 문자열**을 정규식으로 읽어
이름을 판정한다. 위 형태의 산출물은 `"type":"function_field_label","params":["$입장"` 라
실제 확장이 후킹하는 구조와 일치한다(빌드물에서 확인).

인자 없는 함수(`$나가기`)도 정상 빌드·로드·실행된다(2026-08-15 실측).

## 2. 설계 4원칙 — 이걸 어기면 조용히 어긋난다

### ① 한 값의 주인은 한 명

충돌 해소가 **Last-Write-Wins** 라 두 참가자가 같은 변수를 쓰면 하나가 사라진다.
특히 `change_variable`(읽고→더하고→쓰기)은 동시에 부르면 증가분이 유실된다.

- 턴제라면 **지금 턴인 쪽만** 게임 상태를 쓴다. 턴을 넘기는 순간 쓰기 권한도 넘어가므로
  충돌이 구조적으로 0 이 된다.
- 실시간이라면 **슬롯별 변수로 쪼갠다**(`$점수1`·`$점수2`). 공유 합계가 필요하면 각자
  자기 몫만 올리고 **합은 각 클라이언트가 계산**한다.

### ② 리스트는 **통째로** 오간다

동기화 단위가 리스트 전체다(서버 `roomManager.js` 의 `applyItem` 이 키 단위로 저장).
서로 다른 인덱스에 써도 **동시에 쓰면 한쪽이 통째로 덮인다.**

- 참가자별 값은 리스트 한 칸씩 나눠 쓰지 말고 **변수 여러 개**로 쪼갠다.
- 여럿이 "항목 추가"하는 구조는 금지에 가깝다.
- 한 명만 쓰는 리스트(턴제 판)는 안전하다.

### ③ `$` 는 정말 공유할 것에만

커서 위치·입력 상태·연출 타이머처럼 각자 달라야 하는 값에 `$` 를 붙이면 8Hz 로 상대에게
방송된다. 로컬 값은 `$` 없이 짓는다.

### ④ 예약 이름은 읽기만

§1.2 의 다섯 이름에 작품이 쓰면 확장이 곧 덮어쓴다. 상태 표시용으로만 읽는다.

## 3. 깨지지 않는 작품 구조

### 3.1 로컬/온라인 단일 코드 경로

두 모드의 차이는 **"지금 내가 놓을 수 있나"** 한 줄이면 충분하다.

| 모드 | 조건 |
| --- | --- |
| 온라인 | `$턴 == 내슬롯` |
| 로컬(핫싯) | 항상 참 (`내슬롯` 을 매 턴 `$턴` 에 맞춤) |

로컬 모드에서도 `$` 변수를 그대로 쓴다 — 방에 입장하지 않았으면 확장이 **송신 자체를
하지 않으므로**(`EO/inject.js` `pollChanges` 가 `sessionActive` 아니면 조기 반환) 무해하다.
덕분에 규칙·판정 로직을 한 벌만 만들면 되고, **확장 없이도 완성된 작품**이 된다.

### 3.2 판을 세우는 쪽은 하나뿐

전원이 초기화하면 서로의 판을 지운다. **선공(슬롯 1)만** 초기화하고 나머지는 기다린다.

### 3.3 기다리는 조건은 "관찰 가능한 사실"로

수순·카운터로 "상대가 준비됐나"를 판단하면 **지난 대국의 값이 남아 있어** 앞질러 시작한다.
작품의 변수는 세션이 끝나도 초기화되지 않기 때문이다.

```
✗ waitUntil($수순 >= 1)          // 지난 판의 값이 이미 1
✓ 판 위의 돌이 정확히 1개가 될 때까지 기다린다   // 지금 도착한 상태만 참이 되는 조건
```

### 3.4 그리는 주체도 하나 — **상태 기반 렌더러**

상대가 놓은 돌은 `$보드` 같은 공유 상태로만 도착한다. "놓을 때 그린다"(이벤트 기반)로
만들면 내 돌만 보인다. 대신 **공유 상태와 화면 사본의 차이만큼 그리는 루프**를 둔다.

```
그린판(로컬 리스트) ← 화면에 이미 올린 것
매 0.1초: 보드[i] != 그린판[i] 인 칸만 그리고 그린판[i] 갱신
```

- 내 돌·상대 돌이 **같은 경로**로 그려져 "내 화면에만 보이는 돌"이 생기지 않는다.
- 패치를 한 번 놓쳐도 다음 패스가 메운다(**자가 치유**).
- 칸이 비워졌으면(0 으로 바뀜) 개별 클론을 지울 방법이 없으니 **전체 재그리기**를 예약한다.
- 143칸 순회는 `repeat` 로 하면 1칸=1프레임이라 불가능하다 → **`fn.value` 꼬리재귀**
  ([07 §꼬리 재귀](07-runtime-quirks.md#함수-호출은-반복하기의-60fps-틱을-우회-꼬리-재귀-최적화)).

⚠️ 한 패스에서 클론 여러 개를 만들 때 전역에 좌표를 담아 `when_clone_start` 에서 읽으면
**전부 마지막 값에 겹친다.** 상대가 한 턴에 2개를 두는 게임에서 바로 드러난다 —
템플릿을 목표 상태로 맞춘 뒤 복제해 **상속**으로 넘긴다
([07 §회피 패턴 2](07-runtime-quirks.md#회피-패턴-2--엔티티-상속으로-넘기기-자리모양이-목적일-때)).

### 3.5 빠져나갈 구멍을 만든다

- **정원이 안 차면 영원히 대기한다.** `$유저번호` 는 방이 잠겨야 0 이 아니게 된다 →
  대기 화면에 **취소 버튼**(→ `$나가기` → 로비)이 반드시 필요하다.
- **상대 이탈**: `$유저연결상태` 의 상대 슬롯(`정원+1 - 내슬롯`)이 `"끊김"` 이면 부전승.
  방이 잠기기 전에는 리스트가 비어 있으므로 **길이를 먼저 확인**한다. `and_` 는 단락
  평가가 없어 한 줄로 묶으면 범위 밖 접근이 먼저 터진다
  ([07 §boolean_and_or](07-runtime-quirks.md#boolean_and_or에-단락-평가short-circuit-없음)).

### 3.6 용량

방당 변수 키 ≤500 · 리스트 키 ≤500 · 직렬화 512KB, 메시지 56KB, 리스트 1024항목.
143칸 판이 약 300바이트니 보드 게임류는 신경 쓸 일이 없다.

## 4. 서버·확장 없이 검증하기 (핵심)

확장이 하는 일은 **예약 값을 작품에 써 주는 것**이므로, 헤드리스에서 그 값을 직접 넣으면
온라인 로직 대부분을 서버 없이 검증할 수 있다.

| 흉내낼 것 | 방법 |
| --- | --- |
| 확장 설치됨 | `$확장프로그램 = 1` |
| 슬롯 배정 | `$유저번호 = 1`(선공) / `2`(후공) |
| 상대 착수 | `$보드` 리스트에 직접 써넣기 |
| 상대 이탈 | `$유저연결상태 = ["끊김","연결"]` |

이것만으로 **슬롯 분기·후공 대기·상대 착수 렌더·이탈 부전승**이 전부 검증된다
([games/hexo/verify.mjs](../games/hexo/verify.mjs) §7).

```js
const setList = (name, arr) => page.evaluate(({ n, a }) => {
    const l = Entry.variableContainer.lists_.find(x => x.name_ === n);
    l.array_ = a.map(v => ({ data: v }));
}, { n: name, a: arr });
```

**여기서 확인할 수 없는 것** — 확장의 실제 후킹, WebSocket 왕복, 패치 지연·유실,
방향키가 `/project/` iframe 에서 페이지 스크롤을 일으키는지. 이건 실사이트 몫이다.

## 5. 실사이트로 가는 길

1. `.ent` 를 playentry.org 에 업로드
2. online.205.kr 에 작품 등록 (정원·모드 설정) — 등록 계정 ID 가 `$입장` 인자
3. 플레이어가 확장 설치 후 `/project/<id>` 접속
   (만들기 화면 `/ws/` 에서는 확장이 동작하지 않는다)

서버 없이 2인 플레이만 먼저 보고 싶으면 `extensions/entry-online-devtools` 가
playentry 안에서 iframe N개 + 브라우저 내 허브로 돌려 준다(등록 불필요).
