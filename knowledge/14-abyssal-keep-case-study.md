# 심연의 성채 — 실제 블록으로 만든 1인칭 던전

2026-09-10 제작한 [심연의 성채](../games/abyssal-keep/README.md)의 재사용 가능한 설계와
검증 근거다. 제작 당시 [abyssal-keep_007.ent](../games/abyssal-keep/abyssal-keep_007.ent)의
검증 보고서와 소스를 기준으로 한다. **현재 같은 이름의 파일은 검증 당시와 해시가 다르다.**
높이가 고정된 격자 벽과 카메라를 향하는 그림으로 공간을 표현하는 **레이캐스팅 2.5D**다.
임의의 입체 메시, 높낮이가 다른 층, 자유로운 상하 시점은 구현하지 않았다.

`.mjs`는 제작 도구의 입력이고, 작품에는 엔트리 기본 블록과 사용자 정의 함수가 들어간다.
게임 실행에는 외부 JS 모듈이 필요하지 않으며, 그림과 소리를 `.ent` 안에 포함했다.
이 문서는 구현 사례다. 엔진 동작은 [07 런타임 특성](07-runtime-quirks.md),
DSL 작성법은 [04 블록·패턴](04-script-and-blocks.md)이 정본이다.

## 같은 DDA로 원근 벽과 공격 시야 판정하기

플레이어 위치를 `p`, 단위 전방 벡터를 `d = (vx, vy)`, 오른쪽을 `r = (-vy, vx)`로 둔다.
화면 열 `c = 0..N-1`에 대해 `u = 2(c+0.5)/N - 1`, 광선 방향은 `q = d + 0.8u·r`이다.
화면 중심을 기준으로 등각도 광선을 쏘는 대신 **카메라 평면**에서 열을 고른다.

`cast(qx,qy)`는 `p + t·q`가 처음 벽과 만나는 `t`를 반환한다. DDA는 다음 X/Y 격자
경계까지의 `t` 중 작은 쪽으로 한 칸씩 전진한다. `d·q = 1`이므로 이때의 `t`가 바로
전방 깊이이며, 별도의 어안 보정 없이 벽 높이 `300/t`에 쓴다. `300 = 240/0.8`은
이 작품의 논리 화면 폭 480에 맞춘 투영 계수다.

반면 적의 위치가 `e`일 때 `cast(e.x-p.x, e.y-p.y)`에 넣는 벡터는 정규화하지 않는다.
적은 선분의 `t = 1`에 있으므로 반환값이 1보다 작으면 적 앞에 벽이 있다는 뜻이다.
작품은 경계 오차를 허용하여 `t >= 0.98`을 사격·충격파·적의 시야 조건으로 사용한다.
**입력 벡터를 정규화하면 이 반환값의 단위가 바뀐다.** 두 용도를 옮겨 쓸 때 확인할 지점이다.

0에 가까운 방향 성분은 `0.000001`로 보정하고 반환 깊이는 최소 `0.02`로 제한한다.
`ddastep`은 외곽이 전부 벽이고 플레이어가 내부에 있다는 전제로 리스트를 직접 읽는다.
최대 39번의 경계 전진 제한도 현재 19×19 맵에 맞춰져 있다. 맵 크기·외곽·플레이어 위치 정책을
바꾸면 경계 검사와 탐색 한도를 함께 바꿔야 한다.

## 그림을 세로로 나누면 벽 뒤의 일부만 가릴 수 있다

`walls`는 각 화면 열의 깊이를 1부터 시작하는 `depth` 리스트에 저장한다.
몬스터와 아이템은 다음 순서로 그린다.

1. 상대 위치를 전방 깊이 `z = (e-p)·d`, 가로 성분 `s = (e-p)·r`로 변환한다.
2. `z > 0.14`인 개체를 먼 순서로 고른다. 화면 X는 `300s/z`, 기본 높이는 `300/z`다.
3. 원본 그림을 미리 나눈 16개 세로 조각의 화면 X를 각각 계산한다.
4. 조각 중심이 속한 열의 `depth`와 `z`를 비교하여, 벽보다 앞인 조각만 `brush_stamp`한다.

중심 광선 하나로 개체 전체를 표시/숨김하면 벽 모서리에서 몸통이 통째로 나타난다.
조각마다 검사하면 일부만 보일 수 있다. 다만 조각 중심을 샘플링하는 근사이므로 픽셀 단위
정밀 가림은 아니며, 조각 수·벽 열 수가 적으면 경계가 거칠어진다.
검사기는 일부 가린 적의 stamp가 `0 < 개수 < 16`, 완전히 가린 적은 0인지 확인한다.

벽 그림은 층 3종 × 거리 명암 6단계 × 텍스처 가로 위치 16개로 미리 준비한다.
실행 중에는 거리·벽 면 방향으로 모양을 선택하고 폭·높이를 바꿔 찍는다.
바닥 격자선은 카메라 깊이 `0.55`에서 잘라 투영한다. 카메라 뒤의 끝점을 그대로 나누면
선이 뒤집히거나 화면 밖으로 크게 뻗는 것을 피하기 위한 근평면 처리다.

## 계산을 나누되 완성된 결과를 읽게 하기

**벽 캐시:** 벽·바닥을 그리는 오브젝트와 몬스터·아이템을 그리는 오브젝트를 나눈다.
벽은 `(px, py, angle, floor, cols)`가 바뀔 때만 지우고 다시 그린다. 개체는 `frames`를
확인하며 별도로 갱신한다. 카메라가 멈춰도 적은 움직인다. 이동·회전 중에는 캐시 이득이 줄어든다.
현재 맵은 층 안에서 변하지 않는다. 문 개폐·벽 파괴를 추가하면 **맵 변경도 벽 캐시를 무효화**해야 한다.

**길찾기:** 적마다 탐색하는 대신 플레이어 칸을 목표로 하는 BFS 거리 필드를 공유한다.
`navigation`은 플레이어가 다른 칸으로 옮겨가면 `work`에서 탐색하고, 한 프레임에 큐 항목
20개를 처리한다. 완성되면 `navcopy`로 `nav`에 복사한다. 적은 작업 중간의 `work`를 읽지 않는다.
탐색 도중 플레이어가 이동하면 현재 탐색을 끝낸 뒤 새 칸을 대상으로 다시 계산하므로 추적에 지연이 있다.
20칸 제한은 **큐 처리량**이다. 361칸 초기화와 완료 복사는 동기 실행이므로 전체 비용이 매번
20칸으로 제한되는 것은 아니다. 더 큰 맵에서는 초기화·복사도 측정해야 한다.

한 프레임 안의 DDA·작은 순회는 엔트리 값 함수의 재귀 호출로 묶었다.
이미 알려진 [함수 실행 특성](07-runtime-quirks.md#함수-호출은-반복하기의-60fps-틱을-우회-꼬리-재귀-최적화)을 적용한 것이며,
블록 슬롯에 다른 모드의 반복 블록을 넣는 우회는 사용하지 않았다.
공유 임시 변수는 호출 안에서 소비하고, 프레임 양보를 넣거나 여러 실행 흐름에 나눌 때에는
[전역 임시 변수 경합](07-runtime-quirks.md#다중-클론의-repeatinf-본체--글로벌-scratch-변수-race)을 다시 검토한다.
빈번한 전역 변수 조회 비용은 [07 조회 순서](07-runtime-quirks.md#전역-변수-리스트-조회는-배열-탐색이다)를 참고한다.

## 생성·이동·보상에서 유지한 조건

- 맵은 3×3개의 방이다. 각 방 행은 가로 통로로 연결하고, 위아래 방 행 사이에는 적어도 한
  통로를 만든다. 무작위인 것은 통로 위치·추가 연결·기둥과 드롭·유물이다. `roomOrder`와
  적·아이템의 **초기 배치 규칙은 고정**이며, 임의의 방 분할이나 적 위치 추첨은 하지 않는다.
- 좌표→리스트 번호는 `floor(y)*19 + floor(x) + 1`이다. 0 기반 월드 좌표와 엔트리의
  1 기반 리스트를 이 함수에서 연결한다. 외곽 벽은 BFS의 좌우 행 넘김도 막아 준다.
- 시간 차는 `0.001..0.12초`로 제한한다. 너무 낮은 상한은 느린 프레임에서 게임 시간을
  계속 버린다. 제한을 늘리면 한 번의 이동이 커지므로 충돌 세분화도 함께 검토한다.
- 이동을 4개 하위 단계로 나누고 X/Y를 각각 검사해 벽을 따라 미끄러지게 한다. 중심에서
  ±0.18인 네 모서리를 검사하는 방식이며 정확한 원 충돌식은 아니다. 대각 입력에는 0.7071을
  곱한다. 속도 유물은 중첩되므로 현재 하위 단계 수를 모든 속도에 대한 보장으로 일반화하지 않는다.
- `state`는 타이틀 0 / 플레이 1 / 유물 선택 2 / 사망 3 / 승리 4 / 일시정지 5다.
  `lastTime`은 비플레이 중에도 갱신하고, 이동·전투·원정 시간은 플레이일 때만 진행한다.
- 유물은 첫 3처치 뒤 4처치마다, 그리고 다음 층 입장 때 제시한다. 층 경계와 처치 보상이
  가까우면 연속으로 선택할 수 있다. 보스 사망은 승리를 우선 처리하므로 소환수가 남아도 끝난다.

[게임 README](../games/abyssal-keep/README.md#다시-만들거나-검증하기)의 명령으로 재검증한다.

갱신하고 이전 번호의 작품을 덮어쓰지 않는다.

`playthrough-401946.json`은 이 문서가 참조하는 완주 기록이다. 기능별 fixture 검사와 입력만의
완주가 각각 무엇을 확인하는지는 [05 검증 분리](05-host-editor.md#기능-검사와-입력-완주는-별도로-기록한다)에 정리했다.
