# 뮤직비디오 사례 — 그림 순서와 신호로 만든 타임라인

사용자가 제공한 뮤직비디오 작품 `.ent` 를 직접 읽고 뮤직비디오·인트로·컷신에 재사용할 구조를 정리했다. 사용자 분류는 뮤직비디오이며 단일 음악과 연속 그림·자막 레이어가 이를 뒷받침한다.

## 출처와 범위

- 원본: 사용자가 제공한 로컬 `.ent`, 10,040,361 bytes.
- SHA-256: `97a77cb6217216fcbe8040ece1ad858c13f4f0f417e589835e9d92af674f479e`.
- 분석일: 2026-09-10. [증거 JSON](evidence/music-video-remake.json)에 해시·통계 정의·JSON Pointer assertion을 기록했다.
- `temp/project.json`의 `objects[*].script` 문자열을 파싱한 후 분석했다. 아래 경로는 **파싱 후 구조**다. 경로와 object id를 함께 사용하며 block id만 전역 식별자로 가정하지 않는다.
- 정적 구조와 자막 SVG 표본 3장(그림 인덱스 0·1·7)의 문자 형태를 확인했다. **런타임 재생, 소리 길이 실측, FPS, 음악·화면 동기화는 미검증이다.**
- 원본·이미지·음악·가사·전체 스크립트는 복사하지 않았다. 작품 내부 문자열은 분석 데이터로만 취급했다.

## 1. 상대 대기 대신 목표 시각을 비교한다

**정적 관찰.** 주 타임라인 `/objects/6/script/0`은 신호 `78qp`를 받으면 타이머 RESET, 변수 `oinf=0`, show를 실행한다. 첫 반복 `q4tq`는 17회이며 본문은 다음 순서다.

```text
타이머 >= oinf가 될 때까지 기다리기
다음 모양으로 바꾸기
oinf += 1 / 24
```

근거: `/objects/6/script/0/4/statements/0`의 `v6iq`(대기), `onnt`(모양), `ib07`(기한 증가). 증거 assertion `frame-*`.

**추론.** 1/24초 간격의 갱신을 의도한 구조다. 기준 시각과의 차이를 확인할 수 있지만, 조건이 이미 참이어도 그림을 하나씩 넘기므로 오래 멈춘 뒤 현재 프레임으로 곧바로 건너뛰는 구조는 아니다. 첫 기한이 0이므로 첫 변경은 양의 대기 없이 가능하다. 반복 횟수/24를 실측 재생 길이로 쓰면 안 된다.

**재사용 제안.** 시간과 프레임 인덱스를 분리한다. 현재 시각에 맞는 그림이 필요하면 `floor((현재시각-구간시작)*목표fps)`로 인덱스를 계산하고 범위를 제한하는 설계를 검토한다. 이는 원본에 없는 개선안이다. 반복과 wait의 실제 비용은 [07 런타임 지식](07-runtime-quirks.md)이 정본이다.

## 2. 신호로 컷을 전환하고 오디오·그림·자막을 나눈다

**정적 관찰.** 장면은 `7dwq` 하나다. 다음은 코드상 연결이며 실측 초 단위 타임라인은 아니다.

| 단계 | 트리거·시간 기준 | 다음 연결 |
|---|---|---|
| 오디오 | `7y0y`의 when_scene_start | `tqu1` 비대기 재생; duration 메타데이터 19.1초 |
| 도입 1 | `dmnc`의 when_scene_start → timer START → 12회 그림 갱신 | `0ft3` |
| 도입 2 | `yyz0`가 `0ft3` 수신 → timer RESET → 16회 갱신 | `7604` |
| 도입 3 | `26iu`가 `7604` 수신; 별도 스택이 timer >= 1.5 대기 | `78qp` |
| 주 타임라인 | `s6im`이 `78qp` 수신 | 아래 17개 신호 순서 |
| 마무리 | `vucl` | 주 그림·보조 레이어 숨김, 후반 이동 연출 시작 |

주 타임라인 발신 순서:
`ytle → 0h45 → px0p → lwk6 → 7cfs → eiqc → suuy → gumi → ljnw → 2z2u → zguu → ltrm → 21a3 → qbph → si9t → nst8 → vucl`.

근거: `/objects/9/script/0/3`(`artn`), `/objects/8/script/0/4`(`g3e6`), `/objects/7/script/4/1`(`v9y7`)·`2`(`gibm`), `/objects/6/script/0/75`(`itvy`)·`76`(`xy5g`). 오디오는 `/objects/14/script/1/1`의 `vet0`.

**추론.** 영상의 컷 전환을 한 장면 안에서 신호와 show/hide·모양 변경으로 만든다. 오디오와 시각 연출 스택이 분리되어 있으므로 두 시작의 실제 시각 차이는 별도 측정해야 한다.

**재사용 제안.** 신호 이름을 도입·절·후렴·종료처럼 의미 있게 정하고 하나의 진행 오브젝트가 발신하게 한다. 사운드 길이 필드는 메타데이터이며, 실제 오디오 길이와 마지막 큐 시각을 별도 검증한다. [04 블록 레퍼런스](04-script-and-blocks.md)의 소리·메시지 형식과 연결한다.

## 3. 자막도 독립된 모양 타임라인으로 만든다

**정적 관찰.** `ttj0`은 textBox가 아닌 SVG sprite다. `ytle`를 받는 `/objects/11/script/2`는 즉시 다음 모양, timer >= 0.35에 다음 모양, timer >= 0.7에 다음 모양 순서다. `78qp` 수신 스택은 y를 65로 바꾸고 0.35 임계값을 쓴다. 화면 문구 자체는 보관하지 않았다.

근거: `/objects/11/script/2/0`(`zmxa`), `2`(`ar1v`), `4`(`74e1`), assertion `subtitle-*`.

**추론.** 자막을 그림으로 만들면 폰트·배치·변형을 이미지에 담고 타임라인은 그림 순서를 관리한다. 표본 3장 외 모든 그림의 문구와 실제 재생 순서를 시각 검증한 것은 아니다.

**재사용 제안.** 편집 자료에 `cueId, offset, pictureId, x, y`를 기록한다. 순서 의존 nextShape 대신 큐 시작에 명시적 picture id를 지정하면 중간 재생·재시작을 검증하기 쉽다. 문구 수정성이 더 중요하면 textBox를 선택하되 [03 글상자 필드](03-objects-and-assets.md)의 초기화 규칙을 따른다.

## 4. 그림을 재사용하고 변형을 합성한다

**정적 관찰.** `/objects/6/script/0/20`의 `kqod`는 3회 반복 안에서 picture `atjl`로 돌아간 뒤 7회 그림을 넘긴다. 뒤쪽 `/objects/6/script/0/66`과 `72`에는 `flip_y`가 있고 특정 모양으로 다시 이동한다.

또한 `tqc4`에는 `vucl`를 듣는 스택이 2개다. 하나는 크기 변형 반복, 다른 하나는 show 후 0.4초 이동과 0.2초 이동을 연결한다. 근거: `/objects/12/script/0/0`(`kiit`), `/objects/12/script/1/0`(`halb`), `avtz`, `c51h`.

**추론.** 그림 수를 늘리지 않고 반복·반전·이동으로 변화를 만드는 구성이다. 같은 신호로 여러 레이어 또는 서로 다른 속성을 함께 연출하려는 의도를 읽을 수 있다. 실제 동시 시작 프레임과 합성 결과는 미검증이다.

**재사용 제안.** 모양·위치·크기의 쓰기 담당을 정하고 동일 속성에 여러 스택이 쓰지 않게 한다. 큐 진입 시 모양·좌표·반전 상태를 초기화해 앞 컷 종료 상태에 의존하지 않게 한다.

## 5. 구간 RESET은 공유 상태라는 점을 드러낸다

**정적 관찰.** 타이머 조작 블록은 19개(START 1, RESET 18)다. RESET 1개는 이벤트 헤더 없는 스택에 있다. 주 타임라인만 RESET이 16개이며 첫 구간 끝에서는 `message_cast(ytle)` 다음에 RESET이 온다. 동시에 `ytle`를 듣는 보조 그림은 `h8ww=0`을 설정하고, 자막은 같은 타이머의 0.35·0.7을 읽는다.

근거: `/objects/6/script/0/5`(`ko5a`)·`6`(`sdph`), `/objects/5/script/1/0`(`p8ez`)·`1`(`d817`), 위 자막 경로.

**추론.** 이 시간값은 음악 시작부터의 절대 시각이 아니라 여러 차례 0으로 돌아가는 구간 시각이다. RESET과 수신 처리 순서를 정적 코드만으로 안전하다고 단정할 수 없다. 원본에서 동기화 오류가 재현되었다는 뜻도 아니다.

**재사용 제안.** 음악용 전역 시계를 유지하고 `구간경과=현재시각-구간시작`을 사용한다. 초기화 담당 하나가 구간 시작값을 기록한 뒤 신호를 보내게 한다. 엔진 메시지 처리 사실은 [07 메시지 race](07-runtime-quirks.md#message_cast-핸들러는-동시-실행--같은-메시지-다중-리스너-race)가 정본이다.

## 6. 분석기는 편집 흔적과 에셋 형식 예외를 보존한다

**정적 관찰.** `/objects/7/script/0`은 repeat_basic, `/objects/11/script/4`는 wait_until_true로 시작한다. 이벤트 헤더 없는 스택을 자동 실행 타임라인에 넣으면 잘못된 큐와 RESET을 더하게 된다. 시작 버튼 스택도 2개로, 각각 next 장면과 `7dwq` 전환을 요청한다. 장면 하나인 이 파일의 실제 시작 동작은 런타임 확인 대상이다.

에셋에는 SVG 원본과 PNG 동반 파일이 함께 있다. 305개 그림 참조 중 303개는 tar에 있고, 2개는 엔트리봇의 `./bower_components/entry-js/images/media/entrybot*.svg` 기본 경로다. 모든 에셋을 자체 포함한 파일이라고 단정할 수 없다. 소리 참조는 tar에 있다.

근거: assertion `detached-*`, `start-*`, `svg-picture`, `builtin-reference-*`; tar 집계 정의는 증거 JSON에 있다.

**재사용 제안.** PNG 전용 생성을 정책으로 선택하더라도 가져오기 분석기에서 기존 SVG 메타데이터를 오류로 취급하지 않는다. 사용자 에셋 누락, 엔진 기본 자산 의존, 동반 PNG·썸네일을 구분한다. [03 외부 작품 SVG](03-objects-and-assets.md#외부-작품을-읽을-때는-svg도-보존한다)와 [01 바이너리 포맷](01-binary-format.md)을 함께 읽는다.

## 새 작품에 적용할 검증

1. **정적:** 큐 연결, picture·sound id, 초기 프레임, 이벤트 헤더 없는 스택을 확인한다. 그림 수와 실행 프레임 수는 다르다.
2. **로드:** SVG·PNG·MP3와 기본 에셋을 실제 배포 환경에서 불러올 수 있는지 확인한다.
3. **실행:** 최초 실행·재시작 각각에서 음악 시작 횟수, scene, cue, `entity.picture.id`, 타이머를 기록하고 자막·보조 레이어를 함께 캡처한다.
4. **동기화:** 실제 오디오 재생 위치와 큐 시각 차이를 측정한다. 목표 간격 1/24와 실측 FPS를 따로 보고하고 지연·중간 재생 정책을 검증한다.

2~4는 이 첨부에서 통과한 검사가 아니라 새 작품에 이 구조를 옮길 때 필요한 검증 항목이다.

실제 음악 위치를 기준으로 측정하는 절차와 별도 파일의 실행 근거는
[16 음악 동기화](16-music-synchronization.md)를 참고한다. 이 문서의 정적 분석과 검증 범위는 그대로다.
